## Phase 1 – תשתית: Sheets + Apps Script

**מטרה:** מסד הנתונים פעיל + Backend בסיסי שיודע לקרוא ולכתוב.

### משימות

#### 1.1 יצירת קובץ Sheets
- [ ] קובץ חדש בשם `Garage_CRM_DB`
- [ ] יצירת 5 גליונות: `Calls`, `Technicians`, `Customers`, `Assignments_Log`, `Settings`
- [ ] הוספת כותרות עמודות לכל גליון (לפי מסמך האפיון)
- [ ] הקפאת שורת הכותרת בכל גליון
- [ ] Conditional Formatting לסטטוסים בגליון `Calls`:
  - חדש → צהוב
  - משובץ → כחול
  - בטיפול → כתום
  - הסתיים → ירוק
- [ ] הוספת נתוני דמה: 3 טכנאים, 2 לקוחות, 1 קריאה לדוגמה

#### 1.2 הקמת Apps Script
- [ ] פתיחת Apps Script מתוך הקובץ (Extensions → Apps Script)
- [ ] חיבור ה-clasp לפרויקט: `clasp clone <SCRIPT_ID>`
- [ ] יצירת קבצים בקוד:
  - `Code.gs` – נקודת כניסה
  - `Database.gs` – פונקציות CRUD
  - `Calendar.gs` – פעולות יומן
  - `Scheduling.gs` – אלגוריתם שיבוץ (placeholder)
  - `Utils.gs` – פונקציות עזר (Haversine, validation וכו')
  - `Config.gs` – קבועים והגדרות

#### 1.3 פונקציות CRUD בסיסיות
- [ ] `getCallById(callId)`
- [ ] `createCall(callData)`
- [ ] `updateCallStatus(callId, status)`
- [ ] `getAllTechnicians()`
- [ ] `getActiveTechnicians()`
- [ ] `updateTechLocation(techId, lat, lng)`
- [ ] בדיקה: כל פונקציה רצה מהעורך ומחזירה תוצאה צפויה

#### 1.4 פרסום כ-Web App
- [ ] הוספת פונקציות `doGet(e)` ו-`doPost(e)`
- [ ] Deploy → New deployment → Web app
- [ ] הגדרה: Execute as → Me, Who has access → Anyone
- [ ] שמירת ה-Web App URL בקובץ `Config.gs`
- [ ] בדיקה עם Postman / curl

### תוצרים

- קובץ Sheets מוכן עם נתוני דמה
- Apps Script project עם CRUD עובד
- Web App URL פעיל

### קריטריון הצלחה

POST request לקישור ה-Web App יוצר שורה חדשה בגליון `Calls`.

## Phase 3 – ניהול טכנאים וסנכרון יומנים

**מטרה:** כל טכנאי מחובר עם יומן Google משלו, המערכת יודעת לקרוא זמינות וליצור אירועים.

### משימות

#### 3.1 הגדרת טכנאי במערכת
- [ ] הוספת טכנאי ידנית לגליון `Technicians`
- [ ] שיתוף יומן Google של הטכנאי עם חשבון המערכת (הרשאת עריכה)
- [ ] שמירת `calendar_id` בגליון

#### 3.2 פעולות על יומן Google
- [ ] `getCalendarAvailability(techId, fromDate, toDate)` – בודקת זמינות בטווח זמן
- [ ] `createCalendarEvent(techId, callData)` – יוצרת אירוע עם:
  - כותרת: "[סוג תקלה] - [שם לקוח]"
  - מיקום: כתובת מלאה
  - תיאור: תיאור התקלה + לינק ל-Waze + מספר טלפון
  - משך: לפי הערכת זמן הטיפול
- [ ] `updateCalendarEvent(eventId, updates)`
- [ ] `cancelCalendarEvent(eventId)` – למקרה של ביטול קריאה

#### 3.3 בדיקה
- [ ] יצירת אירוע ידני דרך Apps Script
- [ ] וידוא שהאירוע מופיע ביומן הטכנאי בנייד
- [ ] בדיקת Conflict – האם המערכת מזהה חפיפות

#### 3.4 הרשאות OAuth
- [ ] הוספת ה-Calendar scopes ל-`appsscript.json`
- [ ] אישור הרשאות בריצה הראשונה

### תוצרים

- 3 טכנאי דמה עם יומנים מסונכרנים
- פונקציות יומן עובדות מקצה לקצה

### קריטריון הצלחה

הרצת `createCalendarEvent` יוצרת התראה ביומן Google של הטכנאי תוך פחות מ-10 שניות.

## Phase 4 – אלגוריתם השיבוץ האוטומטי

**מטרה:** הלב של המערכת – זיהוי הטכנאי המתאים אוטומטית לכל קריאה חדשה.

### משימות

#### 4.1 פונקציות עזר
- [ ] `haversineDistance(lat1, lng1, lat2, lng2)` – מרחק אווירי בק"מ
- [ ] `isWithinWorkingHours(tech, datetime)` – בדיקת שעות עבודה
- [ ] `getTechCurrentLoad(techId)` – כמה קריאות פתוחות יש לטכנאי

#### 4.2 לוגיקת הסינון
- [ ] קבלת רשימת טכנאים פעילים
- [ ] סינון לפי התמחות (matches issue type)
- [ ] סינון לפי זמינות ביומן בשעה הקרובה
- [ ] סינון לפי שעות עבודה

#### 4.3 לוגיקת הניקוד
- [ ] חישוב ציון לכל טכנאי שעבר סינון:
  ```
  score = (100 - distance_km * 5)
        - (current_load * 10)
        + (urgency_bonus)
        + (rating * 2)
  ```
- [ ] מיון לפי ציון יורד
- [ ] בחירת בעל הציון הגבוה ביותר

#### 4.4 חיבור הכל
- [ ] פונקציה `assignTechnician(callId)` שמבצעת:
  1. קבלת פרטי הקריאה
  2. הרצת הסינון והניקוד
  3. יצירת אירוע ביומן הטכנאי הנבחר
  4. עדכון `assigned_technician` בגליון `Calls`
  5. כתיבה ל-`Assignments_Log`
- [ ] טריגר אוטומטי `onEdit` או `onFormSubmit` שמפעיל את `assignTechnician`

#### 4.5 טיפול במקרי קצה
- [ ] אין טכנאי זמין → סטטוס "ממתין לשיבוץ"
- [ ] כל הטכנאים תפוסים → התראה למנהל
- [ ] טעות בכתובת (lat/lng לא תקינים) → סימון לבדיקה ידנית
- [ ] טכנאי דוחה (ידנית בגליון) → הרצה מחדש של השיבוץ

### תוצרים

- אלגוריתם עובד שמשבץ אוטומטית
- לוג של כל ההחלטות

### קריטריון הצלחה

קריאה חדשה שנפתחת מהטופס מקבלת טכנאי משובץ + אירוע ביומן תוך פחות מ-30 שניות.

## Phase 7 – בדיקות End-to-End

**מטרה:** וידוא שהמערכת עובדת מקצה לקצה בתרחישים אמיתיים.

### תרחישי בדיקה

#### 7.1 Happy Path
- [ ] לקוח פותח קריאה רגילה → משובץ אוטומטית → טכנאי רואה ביומן → מעדכן סטטוסים → הקריאה נסגרת

#### 7.2 קריאת חירום
- [ ] קריאה דחופה במיוחד → עוקפת קריאות פתוחות → משובצת לטכנאי הקרוב ביותר

#### 7.3 אין טכנאי זמין
- [ ] כל הטכנאים תפוסים → קריאה ממתינה → ברגע ששיבוץ משתחרר, נכנסת אוטומטית

#### 7.4 התנגשות יומנים
- [ ] שתי קריאות במקביל לאותו אזור → מערכת משבצת לשני טכנאים שונים

#### 7.5 כתובת לא תקינה
- [ ] לקוח מזין כתובת שלא קיימת → המערכת מסמנת לבדיקה ידנית

#### 7.6 בדיקת עומס
- [ ] שליחת 20 קריאות תוך 5 דקות → אין קריסה, השיבוצים מתעדכנים

### משימות נוספות

- [ ] תיעוד באגים שנמצאו וטיפול בהם
- [ ] כתיבת `README.md` ראשי
- [ ] תיעוד API פנימי (פונקציות Apps Script)
- [ ] מדריך התקנה למפתח חדש (במקרה שתחזור לזה אחרי כמה חודשים)

### תוצרים

- מערכת יציבה
- דוקומנטציה בסיסית

### קריטריון הצלחה

## Phase 8 – שיפורים תחרותיים (אופציונלי)

**מטרה:** סגירת פערים מההשוואה ל-Workiz / Housecall Pro. **לבחירה לפי סדר עדיפות.**

### 8.1 SMS "אני בדרך" 🔴
- [ ] הקמת חשבון Twilio (Trial חינמי) או 019/SMS4Free
- [ ] פונקציה ב-Apps Script שמתריעה SMS אוטומטי כשהטכנאי לוחץ "בדרך"
- [ ] הודעה ללקוח עם ETA ומיקום הטכנאי

### 8.2 חלונות הגעה 🔴
- [ ] שינוי הצגת זמן ללקוח: "בין 14:00-16:00" במקום "ב-14:30"
- [ ] חישוב חלון לפי דחיפות + עומס

### 8.3 מעקב סטטוס חי ללקוח 🔴
- [ ] דף web עם URL ייחודי לכל קריאה (`/track/<call_id>`)
- [ ] מציג: סטטוס נוכחי, מיקום הטכנאי על מפה, זמן הגעה משוער
- [ ] עדכון אוטומטי כל 30 שניות

### 8.4 תיעוד תמונות בשטח 🔴
- [ ] הוספת אפשרות העלאת תמונות באפליקציית הטכנאי
- [ ] שמירה ב-Google Drive בתיקייה לכל קריאה
- [ ] קישור ל-Drive ב-`Calls.notes`

### 8.5 התראות Push לטכנאי 🔴
- [ ] שילוב Telegram Bot כפתרון חינמי
- [ ] התראה לטכנאי על כל קריאה חדשה
- [ ] חלופה: PWA עם Push Notifications API

### 8.6 חשבוניות ירוקות 🔴 (חובה לישראל)
- [ ] אינטגרציה למערכת חשבונית ירוקה (Greeninvoice / EasyCount API)
- [ ] הפקה אוטומטית בסגירת קריאה

### 8.7 הצעות מחיר 🟡
- [ ] תבנית הצעת מחיר לפי סוג תקלה
- [ ] שליחה ללקוח לאישור לפני התחלת עבודה

### 8.8 KPIs לטכנאי 🟡
- [ ] דוח אישי לכל טכנאי
- [ ] זמן תגובה, מספר קריאות, דירוג לקוחות

## הערות לסיום

1. **אל תעצור על שלמות** – POC הוא POC. אם משהו עובד 80%, ממשיכים. תיקונים לעת מצוא.
2. **תעד תוך כדי** – אל תשאיר את הכתיבה לסוף. כותב פונקציה? כותב מה היא עושה במקום.
3. **גרסאות** – commit אחרי כל פיצ'ר עובד. גם אם לא דחוף.
4. **בדוק על משתמש אמיתי** – אחרי Phase 5, תן לחבר/בן משפחה לפתוח קריאת דמה. תקבל פידבק שלא חשבת עליו.
5. **שמור על תיקיית גיבוי** – העתק של ה-Sheets פעם בשבוע למקרה שמשהו נדפק.
